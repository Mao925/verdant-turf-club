# VERDANT — 馬主ゲーム

愛馬を選び、人に託し、長い年月をかけて目標へ挑む一人用のスポーツ経営ゲーム。PC中心、スマートフォンでは経営と軽量表示を使う。Vite・React・TypeScript、既存Three.js、Supabase Free・Googleログインを採用する。

設計と進捗の正本はVaultの `スポーツ経営ゲーム/馬主ゲーム/` と `スポーツ経営ゲーム/PROJECT.md`・`WORKLOG.md`。13回答を反映した設計v0.4に従う。初回の試作URLはP2後、繁殖・親子2世代・死亡を含む正式版はP6後。

## 今回の範囲

P1は永続する馬・暦・台帳、Googleログイン、Supabaseへの保存、端末間再開、通信断の再試行と競合、書出し・復旧、既存3Dへの接続を検証する基盤。市場・本格的な競走・継続相談はP2以降。表示する初期の馬と契約は基盤検証用で、購入体験の完成ではない。

馬券UIを馬主ホームへ置き換える。旧 `verdant-turf-v1` は読み取りと書出しだけに使い、コインを円へ移行しない。元コードはGitのbaselineコミットに保全する。

## 実行

Node.js 22.12以上。`npm ci` の後、`.env.example` を元に `.env.local` を用意する。VITE変数は公開されるため、Supabaseの公開用キーだけを設定する。Googleのクライアント秘密鍵・service_role・DBパスワードを置かない。

```sh
npm ci
npm run dev
npm run typecheck
npm test
npm run build
npm run test:e2e
```

未設定時はログイン設定の案内を表示し、クラウド保存ができるふりをしない。接続先を設定してからGoogleログインを行う。PKCEの戻り先は同じ配信元のルートで、固定の許可URLに登録する。

## Supabaseの設定

1. 自分のSupabase組織にゲーム専用のFreeプロジェクトを作る。有料化は別判断。
2. `supabase/migrations/` のSQLを順に適用する。既存ゲーム外のテーブルは変更しない。
3. Google CloudにWeb用OAuthクライアントを作り、SupabaseのGoogleプロバイダーにIDと秘密鍵を登録。Googleの許可リダイレクトにはSupabaseが表示するcallback URLを使う。
4. Supabase AuthのSite URLと許可リダイレクトに開発用・固定試作用URLを登録。アプリの`.env.local`にはプロジェクトURLと公開用キーを設定する。
5. 実際のGoogleアカウントでログインし、別ブラウザで再開。他人のアカウント、通信断、2端末競合、書出しと取込を確認する。

初期の試作配信はP2後。既存の公開URLは現在の旧版で、P1コードを自動で本番デプロイしない。

## バックアップと検証の区別

自動クラウド保存と端末の未送信保護に加え、検証付きJSON書出し・復旧候補としての取込を行う。クラウド内の旧版はDB全体の障害に対する別バックアップではない。FreeのDB休止・容量・別途バックアップを受け入れる。配信前に運用用の暗号化保管先と定期的なDB書出し・復元手順を確認する。

検証時点：型検査・ビルド、追加14件と既存13件、Chromeの画面検証4件、隔離PostgreSQLでの権限・原子性・再送・同時更新を確認。Googleと実Supabaseには未接続。

`npm test` はドメインと保存制御。`npm run test:e2e` はローカルの画面とIndexedDBを含む再開・失敗の検証。実クラウドとGoogle連携の検証とは別に記録する。DBの検証は `npm run test:db`。Dockerの専用一時コンテナに `supabase/tests/` のSQLを適用し、終了時に破棄する。Chromeがインストールされている環境で `npm run test:e2e` を実行する。普段のブラウザのプロファイルは使わない。

`npm run measure` は一頭を120か月進める合成負荷。資金不足と計測を分離するため初期拠出のみ10億円の検証値にし、実ゲームの初期予算は変更しない。今回の実行では記録約1.28MB、月送りp95約41.5ms。PC/スマートフォンの実機や5場のNPC世界の性能保証ではない。

## 既存資産

Three.jsでコード生成した馬・騎手・競馬場を再利用する。既存の `simulation.js` は短い観戦用の旧計算であり、正式版の実在距離・時計を検証済みとはしない。`scene.js` と旧テストは接続時の回帰検証用として維持する。
